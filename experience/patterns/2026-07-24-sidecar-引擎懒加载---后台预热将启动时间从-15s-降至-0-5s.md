## 背景
hermes-desktop sidecar 集成 sherpa-onnx ASR + VAD + VITS TTS，首次启动需加载模型到内存，耗时 8-15s。用户点击应用后长时间无响应。

## 做法
1. **主进程立即返回 ready**：sidecar 启动后先注册 HTTP 路由，返回 `{"status": "ready"}`，此时模型尚未加载。
2. **引擎懒加载**：模型加载放后台线程，首次调用 ASR/TTS 时才触发 `ensure_model_loaded()`。
3. **后台预热**：sidecar ready 后立即在后台触发一次空 ASR + 空 TTS 调用，完成模型加载。用户下次调用时模型已在内存。
4. **前端立即渲染 UI**：前端收到 ready 信号后渲染主界面，用 placeholder/骨架屏占位，不阻塞用户交互。
5. **状态机驱动反馈**：`idle -> listening -> transcribing -> thinking -> speaking -> idle/error`，每个状态有对应 UI 反馈。

## 反例
sidecar 启动时同步加载所有模型，主进程阻塞 15s 才返回 ready。后果：用户看到白屏 15s，误判应用卡死强制关闭。

## 验证
冷启动后立即调用 ASR，首次延迟从 15s 降至 0.5s（预热已完成）。Task Manager 确认 sidecar 进程内存在 ready 后 2s 内稳定（预热完成）。
